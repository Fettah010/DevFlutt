## 6. Design / architecture

```text
lib/
  main.dart                        # runApp(await bootstrap())
  bootstrap/bootstrap.dart         # single startup path; optional ProviderScope
  app.dart                         # MaterialApp / MaterialApp.router
  app/
    routes.dart                    # AppRoutes path constants (navigation)
    app_router.dart                # GoRouter + guarded redirect extension point (navigation)
    route_guard.dart               # RouteRedirect typedef (navigation)
  core/
    config/app_config.dart         # env + build identity + validation (architecture-core)
    theme/app_tokens.dart          # spacing/radius/motion tokens (architecture-core)
    theme/app_theme.dart           # Material 3 light/dark from tokens (architecture-core)
    routing/                       # (reserved)
    widgets/                       # reusable core widgets (design-system)
    state/provider_scope.dart      # provider container (state-riverpod)
  features/
    home/home_page.dart            # blank example screen
    counter/                       # feature example (feature-example)
      domain/counter.dart
      data/counter_repository.dart
      application/counter_controller.dart
      presentation/counter_page.dart
    showcase/showcase_page.dart    # demo preset
```

**Composition model.** The generator validates the selection, computes the union of
dependencies/permissions/config keys, and runs the `project` brick with feature booleans
(`hasArchitectureCore`, `hasStateRiverpod`, `hasGoRouter`, `hasDesignSystem`, `hasFeatureExample`,
`hasShowcase`) plus `extraDependencies`. Mason conditionals include files and route entries. No regex
rewriting of Dart/Gradle/manifest files.

**Route/provider/module registrations are generator-controlled.** `AppRoutes` holds every path constant;
`app_router.dart` maps constants to screens with conditional entries; the provider scope is generated.
Tests assert the router renders the right screen for a deep link and the error page for an unknown route.

**Environments/flavors.** Typed `AppConfig` reads `APP_NAME`, `APP_ENV`, `API_BASE_URL`, `FEATURE_FLAGS`,
and build identity from `--dart-define`. Gradle product flavors (`dev`, `staging`, `prod`) add an
`applicationIdSuffix` and per-flavor `app_name`. Invalid configuration fails fast with an actionable
message that does not echo raw environment values.

**Fallbacks.** Without `state-riverpod`, bootstrap runs the app directly. Without `navigation`, the app
uses `MaterialApp` with a home screen. Without `design-system`/`feature-example`/`showcase`, their files
and routes are absent.

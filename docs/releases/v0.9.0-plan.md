## 1. Outcome and success definition

Generated apps can opt into a small, coherent UI foundation that is localized, direction-aware, accessible at common text scales, and respectful of reduced motion. English and Arabic examples exercise LTR, RTL, and mixed-direction content. Shared components expose consistent loading, error, empty, offline, message, confirmation, form, list/card, dialog, and bottom-sheet patterns. The blank preset remains lean and receives no ARB files, localization dependency, gallery, or showcase behavior unless explicitly selected.

Claims are limited to the generated components and screens actually exercised. The plan does not promise full accessibility conformance, translation of arbitrary user content, or performance budgets without measured evidence.

## 2. Research and decisions (checked 2026-10-30)

1. **Localization tooling:** use Flutter SDK `gen-l10n` (`flutter_localizations`, `intl`, `l10n.yaml`, ARB inputs and generated `AppLocalizations`). This is the framework-supported toolchain and avoids a competing generator. Keep it opt-in so blank output stays minimal. Flutter requires `flutter: { sdk: flutter }` for `flutter_localizations`; the current module dependency model emits only hosted constraints. Extend the manifest dependency representation explicitly with validated hosted/SDK sources and an SDK name, preserve existing hosted wire format, and test parsing, validation, explain, planning, generation, dry-run, and audit behavior. Do not encode SDK sources as fake version strings. A Flutter 3.47.9 / Dart 3.13.7 generated-project probe resolved `intl: ^0.20.2` to 0.20.3 and generated English/Arabic localization code; analyze and template tests passed. `flutter: generate: true` is required. `synthetic-package` is deprecated and must be omitted from `l10n.yaml`.
2. **Arabic and direction:** use Flutter `Localizations`/`Directionality` and locale-aware `intl` formatters; do not reverse rows or assume alignment from language names. Include Arabic and English ARBs with reviewed translations for every shipped key, and widget tests for RTL, mixed Arabic/Latin text, large text, and direction-sensitive icons/alignment.
3. **Accessibility verification:** apply Flutter's `AccessibilityGuideline` API tests for tap target size, labels, and contrast where supported; add explicit semantics/focus-order and large-text tests for generated screens. Record a manual checklist for screen-reader labels/navigation, keyboard/focus, contrast in light/dark themes, and reduced motion; automation is not a full conformance claim.
4. **Reduced motion:** gate template-owned motion using `MediaQuery.disableAnimations` and use immediate or low-motion alternatives. Flutter animation controllers honor the platform setting, but custom transitions must be tested explicitly.
5. **Architecture:** retain Material 3, existing app-owned `AppTheme`/tokens, Riverpod and GoRouter. Keep the component gallery in the optional `showcase` selection; inspect existing presets before changing them, and only adjust a preset if roadmap intent and compatibility evidence show that gallery selection currently leaks into blank/core output.

Primary sources: [Flutter internationalization](https://docs.flutter.dev/ui/internationalization), [Flutter accessibility testing](https://docs.flutter.dev/ui/accessibility/accessibility-testing), [Flutter accessibility design and styling](https://docs.flutter.dev/ui/accessibility/ui-design-and-styling), [MediaQueryData.disableAnimations](https://api.flutter.dev/flutter/widgets/MediaQueryData/disableAnimations.html). Revalidate API behavior against the pinned Flutter toolchain before implementation. No third-party UI or localization package is justified.

## 6. Performance, security, dependencies, and privacy

No performance budget is added. Keep blank dependency/file output unchanged and measure representative release artifact sizes for blank and localized/design-system variants as descriptive evidence only. `flutter_localizations` is an SDK dependency; `intl` is a hosted dependency whose compatible version and license must be checked at T01. Do not add animation or UI libraries absent a demonstrated gap. No network, telemetry, secrets, permissions, platform-specific native changes, or collection of personal locale data are introduced. Keep translation resources free of user content and avoid logging localized/private text.

## 7. Risks and recovery

| Risk | Mitigation / recovery |
|---|---|
| SDK dependency support changes manifest wire contract or audit output | Add a backward-compatible explicit source enum, retain old hosted form, add schema and compatibility tests; defer implementation if existing CLI consumers would break unexpectedly |
| Generated localization files depend on tool invocation/order | Commit ARBs/config only; document `flutter gen-l10n`; generated output must be deterministic and present after documented generation/build commands |
| Arabic text clips or direction gets manually reversed | Use framework directionality; test mixed strings and large text; inspect generated key screens in RTL and fix layout constraints at source |
| Contrast and guideline checks produce false confidence | Treat them as bounded automated checks; record manual screen-reader/focus/contrast checklist and exact platform evidence |
| Custom route animation ignores reduced motion or impairs startup | Use framework setting and explicit disabled-motion tests; keep defaults short and transitions optional/configurable within existing architecture |
| UI milestone expands into a large design framework | Keep to roadmap-listed reusable patterns and current Material 3 tokens; defer broad redesign/extra widgets to `docs/DEFERRED.md` |
| v0.8 candidate base is not remotely green | Do not start v0.9 production code; repair the predecessor check first while retaining the isolated plan/worktree |

Rollback: revert only v0.9 commits on this branch. Never alter v0.8 commits, the main workspace, existing user changes, or published refs.

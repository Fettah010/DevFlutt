## 1. Delivered outcome

Implemented shared Firebase and Supabase cores, Firestore and Postgres/PostgREST data
modules, independent `--backend` selection, the `commerce` and Android `full` presets,
and the generated-project matrix expansion. The local V2 gate, exact-candidate CI, all 25
generated-project cases, Patrol UI tests, and the protocol failure-gate self-test have been
observed. After the probe cleanup refinement, `.\tool\verify\verify.ps1` passed against the
current worktree, including the complete Flutter/generator suites, Android debug/release
builds, license inventory, secret and dependency scans, and release-permission inspection.
Candidate `69487a71fd63170ef39953ee95bd6ba568734298` passed all CI and Patrol checks except
one generated `recommended` debug build, where SDK Manager failed while unpacking NDK
28.2.13676358. A bounded, version-verified NDK-install retry was added to the generated-project
workflow, but its first CI attempt failed because `sdkmanager` is not on PATH. The workflow now
calls it via the configured Android SDK root. Exact-candidate CI run `41349473466` passed all
32 jobs, including all 25 generated-project cases; Patrol run `41349473440` also passed on
candidate `7f9dee5c608e987cc655b8268c6afb67b8aa9860`. The Redmi 8 (Android 10/API 29, MIUI V125)
uses a device-aware theme assertion.
The updated Patrol runner now foregrounds the app when MIUI leaves the launcher visible; an
earlier physical-device run exited 0 with all four tests passing in 1m58s. Two later smoke
retries timed out at MIUI's USB confirmation. A subsequent manual approval installed the
exact blank release APK; the non-installing probe verified its bytes and recorded five
process-cold startup samples, total PSS, available launch-only frame stats, and raw evidence.
These measurements apply only to the named APKs and device. `--keep-installed` remains
unverified. Release AAB sizes are measured for the four named presets and seven provider
compositions. Version metadata is now aligned locally; the version-aligned core, recommended,
and full APKs were rebuilt and remeasured (E-024). The resulting source changes still need
their own exact-candidate release checks, so V3 is still blocked. PR #12 remains a draft; no
merge or release claim is made.

## 9. Known issues, deferred work, owner actions

- **Release blocker:** the four named presets each have one five-launch Redmi 8 measurement
  session, but this is descriptive evidence rather than a repeated baseline; the single
  launch-only `gfxinfo` frame per preset does not validate interactive frame pacing. Do not
  make representative jank or performance-threshold claims from these observations. Redmi 8
  Patrol coverage passed 4/4 in the local run; later smoke retries timed out because MIUI's
  manual confirmation was not approved before timeout. Do not automate around this OS security
  prompt.
- Release AAB builds succeeded but emitted a host Android SDK XML v4/tooling-version warning
  and upstream Kotlin Gradle Plugin migration warnings for Firebase and WorkManager plugins.
  Recheck the Android command-line tools and plugin migration status before future Flutter
  upgrades; these warnings did not fail the current pinned-toolchain builds.
- Live Firebase and Supabase flows require owner-provided projects and credentials.
- iOS builds for provider modules require a macOS runner and remain unverified.
- Pairwise module combinations and broader release hardening remain v0.10.0 work.

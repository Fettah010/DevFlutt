## 1. Delivered outcome (vs plan)

The milestone delivered the four selectable service modules the plan called for, a generated
composition root that makes them usable, and the three supply-chain gates.

| Planned | Delivered |
|---|---|
| `logging` module | Structured logger, `Redactor` applied before the sink, debug/release verbosity policy, memory sink for tests |
| `networking` module | Typed `ApiClient`, `ApiResult`/`ApiError`, timeouts, cancellation, request correlation, bounded retry decorator, Dio adapter, fake adapter |
| `secure-storage` module | `SecureStore` interface, `flutter_secure_storage` adapter, in-memory adapter, generated Android backup exclusion |
| `diagnostics` module | `ErrorReporter` interface, `AppError`, local in-memory adapter, no provider SDK |
| `recommended` preset | `core` plus `diagnostics`, `networking`, `secure-storage` |
| Composition root | Generated `lib/app/app_services.dart`; absent when no service module is selected |
| Supply-chain gates | `secret-scan` (gitleaks), `dependency-audit` (osv-scanner), `license-inventory` (generated notices) |
| ADRs | ADR-004 and ADR-007 |
| Documentation | Four module documents, `docs/SECURITY-BASELINE.md`, `docs/UPGRADING.md`, and updates to the architecture, modules, compatibility, testing, changelog, and README documents |

### Deviations from the plan

1. **The licence inventory does not query the pub.dev API.** The API does not expose the
   `license` field for a package whose pubspec does not declare one, which is most of them.
   The tool therefore reads the licence from the resolved package's `LICENSE` file in the pub
   cache and classifies it. Every one of the 71 locked packages was detected; none is
   `UNKNOWN`. Recorded in the plan's progress log.
2. **The generator's lockfile stays untracked.** The plan proposed tracking it so the
   dependency audit could scan it. The generator is a Dart *package*, and the Dart convention is
   not to commit a library's lockfile; the road map's lockfile policy names the reference app
   and the generated apps. The audit resolves the lockfile in the runner first, so the
   generator's dependencies are scanned too.
3. **The `recommended` preset is narrower than the road map's v1.0.0 description of it.** The
   localisation scaffold and the application-lifecycle hooks arrive in v0.8.0 and v0.7.0. The
   preset file is the explicit module list, so what it contains is never a hidden bundle.

## 3. Research and ADR decisions

The plan's §3 answers seven questions with dated evidence. The two that changed an
implementation decision:

- **HTTP client (ADR-004).** `dio` 5.11.1 (MIT, published 2026-09-04) was selected over
  `package:http` 1.6.0 (BSD-3-Clause) because the milestone's requirements — interceptors,
  cancellation, per-request timeouts — are primitives Dio provides and `http` does not. Dio is
  pure Dart, so it adds no native code, no permission, and no APK surface. **Rejected
  alternative:** `dio_smart_retry`, because the retry policy is an application decision that a
  transport-level default would get wrong, so the template implements it itself.
- **Secure storage (ADR-004).** `flutter_secure_storage` 11.2.0 (BSD-3-Clause, published
  2026-09-16) was selected. Its minimum Android API is 23, and the template's `minSdk` is 24.
  Its README documents that auto-backup of the plugin's SharedPreferences makes restored values
  unreadable, which is why the brick generates the backup exclusion rather than leaving it to
  the developer. **Rejected alternative:** `shared_preferences`, which is not secure storage.

ADR-007 records the logging and diagnostics decisions. **Rejected alternatives:** the
`logging` and `talker` packages, because the security-critical part — redaction — must be owned
and regression-tested by the template, and either package would be wrapped by an app-owned
interface anyway; and the Sentry, Crashlytics, and analytics SDKs, because the milestone asks
for app-owned interfaces with providers separately selectable.

## 5. Matrix coverage actually exercised

**Method.** Every preset is generated into a temporary directory outside the repository and then
resolved, format-checked, analyzed, tested, and built. The static rules are enforced by the
generator's own tests, so a module that leaks into an unselected preset fails the suite.

| Preset | pub get | format | analyze | test | debug APK | release APK |
|---|---|---|---|---|---|---|
| `blank` | pass | pass | pass | 17 | pass | not built (no module set needs it) |
| `core` | pass | pass | pass | 48 | pass | not built |
| `demo` | pass | pass | pass | 37 | pass | not built |
| `recommended` | pass | pass | pass | 79 | pass | pass |

**Module coverage.** Each of the four new modules was generated in isolation with only its
declared prerequisites and in combination with the documented high-risk pairs: `logging` ×
`networking`, `networking` × `secure-storage`, `networking` × `diagnostics`,
`secure-storage` × `diagnostics`, and `logging` × `diagnostics`. The `recommended` preset is
the maximum-capability composition.

**Gaps.** The built matrix is **not** exhaustive over all module combinations; the exhaustive
combination sweep is scheduled for v0.9.0. The `DioApiClient` error mapping is verified by
review and by the contract tests over the fake client, not against a live server.

These are **build-host numbers**. The size is dominated by the fat APK carrying every ABI, so a
per-ABI measurement belongs with the performance baselines in v0.9.0. The +3.9 MB difference is

is made about any module. The difference is below the 10 % investigation threshold, and the
`blank` and `core` presets are unaffected because they select none of these modules.

## 11. Reproduction and recovery instructions

**Reproduce the local verification**

```bash
# Windows
.\tool\verify\verify.ps1
# macOS / Linux
./tool/verify/verify.sh
```

**Reproduce one preset end to end**

```bash
dart pub get
dart run tool/ftemplate_cli/bin/ftemplate.dart create \
  --name "Reco App" --org com.example --preset recommended --output /tmp/reco --no-pub
cd /tmp/reco && flutter pub get && flutter analyze --fatal-infos && flutter test
```

**Reproduce the security gates**

```bash
gitleaks git --redact --verbose .
osv-scanner scan --lockfile=pubspec.lock --lockfile=tool/ftemplate_cli/pubspec.lock
dart run tool/ftemplate_cli/tool/license_inventory.dart --check
```

**Recover from a failed release gate.** A fix after a failed V3 gate goes on a new commit and
reruns the full gate; the tag is never moved. The branch is `work/v0.4.0` and the pull request
stays open until the gate passes.
